착수할 항목: `$ARGUMENTS` (비어 있으면 후보를 골라 준다)

이 커맨드는 **고르는 것까지**가 일이고, 그다음 착수·보고 규칙은 `board` 스킬에 있다.
규칙을 여기 복사하지 말고 그 스킬을 로드해 따른다.

## 절차

### 1. 인자가 있으면 픽커를 건너뛴다

`$ARGUMENTS` 에 참조(`rocky-12` / `12` / raw id)가 들어 있으면 그건 "이 항목을 맡아라" 다 —
픽커를 건너뛰고 **4번(고른 항목을 읽는다)** 으로 간다. 참조가 아닌 문장이면(예: "p1 만")
후보를 좁히는 조건으로 읽는다.

### 2. 후보 조회

```bash
rocky-todo next          # cwd 의 git repo 이름으로 보드 유추, 상위 8개 (텍스트)
```

**`--json` 을 쓰지 않는다.** 텍스트 출력이 이미 사용자에게 그대로 보여줄 형태다 — JSON 을
받아 다시 렌더하면 payload 를 읽고 문장을 짜는 시간만 붙는다.

- 후보가 0건이면 `rocky-todo next --all` 로 한 번 더 — 이 레포에 보드가 없을 수 있다.
- `rocky-todo` 가 없거나 데몬이 안 뜨면 MCP `todo_list { board }` 로 폴백해 직접 랭킹한다.
  이때 **"주인 없는 진행중" 판정은 못 한다** — `doingState` 는 REST 응답에만 실린다. 그 경우
  랭킹이 거칠어졌다는 사실을 한 줄로 밝힌다. 데몬이 아예 안 뜨면 가짜 목록을 만들지 말고
  `rocky-todo daemon status` 를 안내하고 멈춘다.

랭킹 기준은 `src/next.ts` 에 있다(주인 없는 doing → 마감 → 우선순위 → 최근 댓글, 우산 항목
제외). 여기서 다시 정렬하지 않는다 — 받은 순서가 곧 순위다.

### 3. 목록을 그대로 보여주고 고르게 한다

CLI 출력을 **그대로** 옮긴다. 재작문·재정렬·요약 금지 — 받은 줄이 곧 순위이고, 손대는 만큼
목록이 늦게 나타난다. 뒤에 한 줄만 덧붙인다:

```
번호나 참조로 골라 주세요. 더 보려면 `rocky-todo next --limit 12`.
```

- **AskUserQuestion 을 쓰지 않는다. 되살리지 말 것.** 툴 질문은 호출 블록이 전부 만들어져야
  렌더돼서, 목록이 한 줄씩 나타나는 체감을 낼 수 없다. 이 커맨드는 "빨리 눈에 보이는 것" 이
  클릭 한 번보다 중요하다고 판단해 그쪽을 택했다(2026-07-30).
- 후보가 1건뿐이면 묻지 말고 그 항목으로 간다.
- 사용자가 번호로 답하면 그 줄의 **완전 참조**(`rocky-todo-21`)로 옮겨 4번으로 간다 — 맨숫자를
  그대로 다른 보드에 쓰면 엉뚱한 항목이 잡힌다.

### 4. 고른 항목을 읽는다

`todo_list { id: "<ref>" }` 로 상세 + 히스토리 + 댓글을 읽는다. 진행중이던 항목을 이어받는
경우(`이어받기(…)` 근거)에는 **어디까지 됐는지 먼저 요약**하고 시작한다 — 히스토리와 댓글이
그 정보의 유일한 출처다.

읽어도 무엇을 원하는지 모호하면 `start` 전에 묻는다. `start` 는 "지금 내가 잡고 있다" 는
신호라 되돌리는 비용이 있다.

### 5. 어디서 할지 — 보드가 이 레포가 아닐 때만 묻는다

고른 항목의 보드가 cwd 의 레포와 같으면 **묻지 않고 여기서 한다**. 다르면 한 줄로 묻는다
(여기서도 툴 질문을 쓰지 않는다 — 3번과 같은 이유다):

- `여기서 진행` — 다른 레포 항목을 이 세션에서 다룬다(문서·조사처럼 코드를 안 건드릴 때).
- `새 세션 띄우기` — `rocky-todo spawn <ref>`. 그 todo 전용 워크트리에서 백그라운드로 돈다.
- `다른 세션에 넘기기` — `rocky-todo sessions` 로 후보를 보고
  `rocky-todo handoff <ref> --session <name> --json`. **여기서 끝내지 마라**: 이 호출은 큐잉일
  뿐이고, 대상이 idle 이면 배달되지 않는다. 응답의 `poke` 를 그대로
  `SendMessage { to: poke.to, message: poke.message }` 로 보내 대상의 턴을 열어라 — 그 턴에
  훅이 상세 지시를 주입한다.

spawn/handoff 를 골랐으면 이 세션은 결과 위치만 한두 줄로 보고하고 끝낸다 — 그 작업을 여기서
같이 하지 않는다.

### 6. 착수

`board` 스킬의 에티켓을 따른다 — `todo_status { action: "start", actor: "claude-code" }` 로
표시하고 시작, 진행 보고는 `comment`, 끝나면 `done`.

## 하지 않는 것

- 후보를 고른 것으로 `done`/`archive` 를 하지 않는다. 이 커맨드는 착수까지다.
- 한 번에 두 건 이상 `start` 하지 않는다. 여러 건을 하고 싶다는 요청이면 순서만 정해 주고
  첫 건만 start 한다.
- 후보가 없으면 새 todo 를 만들어 채우지 않는다. "열린 항목이 없다" 를 그대로 보고한다.
