# 맥 앱 — 메뉴 막대, 할 일 창, 에이전트 아바타

> rocky 를 **고치는** 에이전트용 개발 문서. 쓰는 법은 `README.md` "맥 앱". 2026-10-27 오너 요청으로 만들었다 — 웹 UI 는
> 그대로 두고, 네이티브여야 나은 자리(메뉴 막대에 늘 보이는 상태, 창 하나로 여는 보드)부터 작게 시작한다.

## 규칙

- **데몬의 클라이언트다.** 상주 서버가 아니고 저장하지 않는다. REST 로 읽고 쓰고 `/api/events` SSE 로 갱신을 받는다. 모든 요청에
  `x-rocky-actor` 와 `x-rocky-client: mac` 을 붙인다(사용 로그의 클라이언트가 `mac` 이 된다 — 서버는 헤더를 먼저 본다).
  데몬·`rocky_core` 는 고치지 않는다 — 앱이 필요로 하는 응답이 없으면 그건 데몬 쪽 별도 변경이다.
- **30일 동안 `mac` 클라이언트 사용이 0이면 걷는다**(`rocky usage --since 30d` 의 클라이언트 줄). ratatui TUI 가 90일 0회로 걷힌 전례와 같은 기준이다.
- **언어 경계의 가장자리다.** Swift 는 `mac/` 안에만 있다. 판정 로직을 Swift 로 새로 만들지 않는다 — 데몬이 낸 값(`ready`·`doingState`)을
  그대로 쓰고, 화면용 규칙은 웹·TUI 의 사본이다(`slices(for:)` = `web/lib.ts` 의 `slicesFor`, `boardGroups` = `tui/rows.ts` 의 보드 트리).
  한쪽 규칙을 바꾸면 사본도 같이 고친다.
- **쓰기는 보내고 SSE 를 기다린다.** 상태 변경(`POST /api/todos/:ref/status` 의 `{ action }`)·추가(`POST /api/todos`)는 웹·TUI 와 같은 요청이고
  낙관적 갱신이 없다. SSE 프레임은 150ms 로 모아 건드린 묶음만 다시 받는다.
- **SSE 는 바이트로 줄을 자른다.** `URLSession.AsyncBytes.lines` 는 빈 줄(프레임 끝)을 넘겨주지 않는다. 끊기면 1s→2s→…30s 로 다시 붙고,
  붙을 때마다(첫 연결도) 전부 다시 받는다. 간격은 10초 넘게 붙어 있다 끊긴 것만 처음으로 되돌린다(TUI 와 같다). 요청의 무응답 제한은
  하루로 둔다 — 데몬은 바뀐 것이 있을 때만 보내서 기본 60초면 조용한 동안 계속 끊긴다.
- **PR 알림은 띄우지 않는다.** 머지 후보·충돌 배너는 데몬이 이미 띄운다(`rockyd::prwatch::osascript_notifier`). 앱은 메뉴에
  열린 PR 중 `ready` 이고 초안이 아닌 것을 목록으로만 보인다. 머지는 사람 몫이다.
- **에이전트 상태는 `GET /api/sessions` 를 묻는다** — 세션 목록은 SSE 로 오지 않는다. 아바타가 보이면 15초, 끄면 60초(웹 에이전트 탭의
  `POLL_MS`·`IDLE_POLL_MS` 와 같다), 메뉴를 열 때·아바타를 켤 때 한 번 더. 데몬이 `claude agents --json` 을 3초 캐시하므로 더 자주 묻지 않는다.
  묶음(`agentPhase`)과 둘째 줄(`needs`·`detail`)은 웹 `web/agents.ts` 의 사본이다. 메시지·멈추기는 웹 에이전트 탭 몫이다(아바타를 두 번 누르거나 오른쪽 클릭 메뉴로 `/?view=agents`). 한 번 누르는 건 아무것도 열지 않는다 — 끌어 옮기다 놓는 것과 헷갈려 매번 웹 UI 가 떴다.
- **아바타는 보이기만 한다.** 화면 구석의 떠 있는 패널(포커스를 가져가지 않고 모든 Space 에 뜬다)이 가장 급한 상태 하나를 보인다 —
  내 차례(background `blocked`)면 껑충 뛰고 주먹 인사를 하고(말풍선에 `needs`, 누르면 닫히고 글이 바뀌면 다시 뜬다), 도는 세션이 있으면 주먹을 들어 두드리고, 다 쉬면 엎드려 숨만 쉰다. 배너·소리는 내지 않는다.
  다만 일하거나 기다리는 세션을 마지막으로 본 뒤 5분(`Drowsiness.awake`)은 잠들지 않고 깨어 있다(`awake` — 망치 없이 돌아다니며 마우스 쪽을 보다 쉬는 동작을 한다).
  interactive 세션은 답을 마치면 바로 쉬는 중으로 묶여, 바로 잠들면 사람과 주고받는 내내 자는 것처럼 보였다(2026-11-06 오너 지적). 묶음 규칙(`agentPhase`)은 웹과 같은 그대로 두고 아바타만 늦게 잠든다.
  같은 동작만 되풀이하지 않게 몸짓을 세 층으로 쌓는다 — 바탕 루프(숨 · 기분 동작) 위에 작은 동작을 가중 랜덤으로 얹고(직전 것은 빼고), 드문 사건(튜브)은 `Roamer` 가 일으킨다.
  도는 중이면 망치를 3-7번(박자 0.7-0.95초를 매번 새로) 내리치고 두리번 · 땀 닦기 · 팔 돌리기 · 발 구르기 · 잠깐 앉기 중 하나를 하고, 창 끝에 서 있으면 내려다보기가 후보에 든다.
  내 차례는 처음 2.4초 동안 한 번 껑충 뛰고 주먹 인사를 하고, 그 뒤엔 마우스 쪽을 보고 서 있다가 10-20초마다 손만 흔든다. 기다리는 세션이 바뀌면 다시 크게 알리되,
  같은 세션이 3분(`cheerCooldown`) 안에 다시 기다리면 건너뛴다 — 네 번 뛰던 4.8초를 일과 기다림을 오갈 때마다 처음부터 되풀이해 자꾸 튀었다(2026-11-06 오너 지적).
  착지하면 0.2초 쭈그리고, 점프 전에는 0.3초 쪼그린다.
  걸을 때는 한 발씩 들어 디딘다(`RockyKit.Feet`) — 디딘 발은 화면에 붙어 있고 몸만 그 위를 지나간다(2026-11-06 오너 지적 "좀 더 자연스럽게" — 캡처를 프레임 단위로 재 보니
  두 다리를 시간 박자로 같은 쪽으로만 흔들고 발이 몸과 같이 45pt/s 로 미끄러졌다). 걸음은 시간이 아니라 걸어온 거리로 센다 — 한 바퀴(두 걸음)는 12-21pt(빠를수록 길게)이고
  다 빨라지면 0.23초에 한 걸음, 가는 쪽 발이 먼저 나간다. 든 발은 0.18초 동안 2.5pt 높이로 옮겨 몸이 그때 있을 자리 앞쪽에 디디므로 빨라지든 줄든 디딘 발이 미끄러지지 않는다.
  서면 엉덩이 아래에서 1.5pt 넘게 벗어난 발을 먼 발부터 한 발씩 모으고, 뛰거나 떨어지거나 튜브에 들면 발을 몸과 같이 옮기며 0.08초쯤에 엉덩이 아래로 끌어온다(뛰기 전 쪼그리는 동안은 딛고 있다).
  그림은 다리 조각을 디딘 자리로 옮기고(발바닥 가운데가 그 자리에 오게) 1pt 에 1.6도씩 기울이며, 윗몸(팔 · 몸통 · 얼굴)만 엉덩이 줄 가운데를 축으로 디딘 발 쪽으로 3도 기울이고
  든 발 쪽 팔을 벌린다. 걷는 동안 윗몸은 앞으로 2도 숙인다. 튜브 안에서 기어갈 때만 예전처럼 시간 박자로 몸을 흔든다(줄어든 채 빨리 지나간다).
  출발과 정지도 한순간에 하지 않는다 — `Roamer` 가 180pt/s²(`walkAccel`)로 0.25초에 걸쳐 빨라지고, 설 자리(서성일 자리 · 사람 곁)가 다가오면 그 안에 설 만큼 줄여 그 자리에 서며,
  가끔 쉴 때도 줄여 다 멈춘 뒤에 선다. 돌아서면 섰다가 다시 빨라진다. 돌아설 때는 0.22초 동안 몸 폭을 14% 좁혔다 펴며 그 가운데에서 좌우를 뒤집는다 — 한 프레임에 뒤집던 때는 툭 튀어 보였다.
  움직임은 끊기지 않게 다듬는다(2026-11-06 오너 지적 — 손 흔들기와 통통 튀기가 어색했다). 동작 사이는 0.35초 smoothstep 으로 섞고, 손 조각(내린 손 · 편 손)은 한 프레임에 갈아 끼우지 않고
  겹쳐 바꾼다(`Arm.from` · `fade`). 손 흔들기는 팔을 다 올린 뒤 초당 1.6번 ±20도로 젓는다(2.4초). 껑충은 0.15초 딛고 0.45초 포물선으로 뜨고, 걷기의 들썩임은 든 발 높이의 제곱(`sin²`)이다 —
  `|sin|` 이나 sin 높이처럼 바닥에서 뾰족하게 꺾이는 곡선을 쓰지 않는다.
  자세를 바꿀 때도 한 프레임에 갈아 끼우지 않는다(2026-11-06 오너 지적 "자세 바꿀 때도 자연스럽게" — 캡처를 보니 서 있다가 한 프레임 만에 엎드리고, 표정과 점프 · 갸웃 그림이 툭 바뀌었다).
  기분 · 움직임(`RoamAction`) · 몸짓이 바뀌면 컨트롤러가 장면 층(`RockyKit.Shifts`)을 하나 얹고, 그림은 층마다 자세를 짜서 아래 층부터 섞는다 — 움직임만 바뀌면 0.2초,
  기분이나 몸짓이 바뀌면 0.4초, 통째 그림으로 들 때 0.5초, 날 때 0.9초. 바뀔 때의 흐르는 값(쪼그림 · 뜬 정도)은 아래 층에 그대로 남는다.
  통째 그림(자기 · 갸웃 · 뛰는 중)마다 그 그림과 거의 겹치는 관절 자세(쌍둥이, `RockyPose.twin`)를 두고, 관절이 쌍둥이 자세로 간 뒤에 그림을 겹쳐 바꾼다 —
  앞 절반은 아래 것이 다 보인 채 위 것이 짙어지고 뒤 절반은 위 것이 다 보인 채 아래 것이 옅어진다(둘 다 반투명이면 그 사이로 뒤가 비친다). 표정도 같은 조각은 그대로 두고 다른 조각만 이렇게 바꾼다.
  잠들 땐 0.5초 주저앉으며 눈을 감고 엎드린 뒤 1.0-1.4초에 잠 그림으로 바꾸고, 깨면 0.9초에 걸쳐 일어나며 그동안(`Roamer.wakeUp`, 1초) 걷지 않는다.
  갸웃은 0.45초 동안 손을 머리로 올린 뒤 그림으로 바꾸고 0.6초에 걸쳐 회색이 된다. 점프는 뜬 정도(`Roamer.flight`) 0.1 까지 쌍둥이 자세로 펴고 0.08-0.2 에 그림으로,
  0.72-0.84 에 다시 관절로 바꿔 다리를 뻗으며 내려앉는다(그림자는 뜨면서 옅어진다). 쌍둥이 자세와 이 시간들은 레포 밖 프로젝트 파일 `mac-avatar/pose/`
  (`pose.js` 앱과 같은 셈 · `tune.js` 그림과 쌍둥이를 겹쳐 맞추기 · `run.js` 옛 그림과 나란히 그리기)로 맞췄다 — 바꾸면 그쪽도 같이 고친다.
  몸을 위아래로 흔드는 폭은 작게 둔다 — 걷기 들썩임은 발을 들 때만 화면에서 0.4pt, 손 흔들 때는 기울기만, 망치질 반동은 2.5. 초당 3번 넘는 들썩임이 크면 계속 통통 튀어 정신없다(2026-11-06 오너 지적).
  망치를 내리친 충격도 한 프레임에 꺾지 않고 0.05박자에 걸쳐 차오른다.
  고르는 판정은 `RockyKit` 의 `Choreographer`(후보표 · 가중치 · 길이 범위) 순수 함수이고, 자세(`RockyPose`)는 고른 토막을 그리기만 한다. 몸짓은 돌아다니기를 꺼도 고른다.
  그림은 오너가 고른 시안(프로젝트 파일 `mac-avatar/concept-face.jpg`의 네 자세)을 윤곽대로 잘라 낸 조각 PNG 20개(`Resources/rocky/`)를 짜 맞춘 것이다(`RockyArt`) —
  몸통 · 다리 둘 · 팔(내린 손 · 편 손 · 머리에 댄 손) · 눈 · 눈썹 · 입 조각을 서 있는 자세의 좌표에 놓아 움직이고, 자기 · 갸웃 · 뛰는 중은 시안의 그 자세를 통째로 그린다.
  시안 픽셀을 그대로 쓰고 엄지만 지웠다(오너 결정 2026-10-29 — 도형으로 다시 그리니 질감과 자세가 시안과 달라졌다. 세 손가락이 컨셉이라 엄지척 대신 주먹 인사를 쓴다).
  다리를 셋 이상으로 늘리거나 몸 아래로 곧게 뻗는 것을 붙이지 않는다(오너 결정 2026-10-29 — 세로로 길쭉한 실루엣은 민망하게 읽힌다).
  조각을 자르는 트레이서(Python)와 앱과 같은 셈으로 그려 보는 하네스, 시안 비교는 레포 밖 프로젝트 파일 `mac-avatar/trace/`에 있다 — 조각을 다시 자르면
  `RockyArt` 의 좌표 표(`Sprite.origin` · 팔의 `pivot` · `theta` · 얼굴 조각의 `from`)를 그 출력(`rig.json`)에 맞춰 같이 고친다.
  .app 은 `bundle.sh` 가 복사한 `Contents/Resources/rocky/` 에서, `swift run` 은 SwiftPM 리소스 번들에서 읽는다(`Bundle.module` 은 .app 에서 번들을 못 찾으면 멈추므로 쓰지 않는다). 그림을 못 읽으면 회색 돌 하나를 그린다.
  **돌멩이 그림체**(`PebbleRocky.swift`, 2026-11-06 오너 요청 "원작 느낌 없이 돌맹이 캐릭터로")는 위 "다시 그리지 않는다"의 예외다 — 오너가 새 그림체를 명시적으로 골랐다.
  원작 조각은 그대로 두고 고치지 않는다. 원작의 사암색 · 금 · 청록 점을 다 뺀 꼭대기가 한쪽으로 쏠린 회색 바위에 볼터치와 ω 입을 단 것이다(처음의 위가 볼록한 돔은
  오너가 "응가같은 모양"이라 해서 각진 바위로, 다시 "직사각형에서 벗어나 봐"라 해서 기운 바위로 바꿨다. 시안과 자세 시트는 프로젝트 파일 `mac-avatar/simple-style/pebble-*`).
  원작 조각과 **같은 칸 좌표**(몸통 가운데 · 발바닥, 엉덩이 · 어깨만 조금 안쪽)에 그려 같은 `RockyPose` 를 받는다 — 걷기 · 발 디딤 · 몸짓을 따로 짜지 않는다.
  통째 자세(갸웃 · 뛰는 중)는 그릴 조각이 없어 관절 자세로 바꾸고(`PebbleRocky.joints`), 잘 때는 팔다리를 다 넣고 바닥에 내려앉아 그냥 돌이 된다(`PebbleRocky.asleep`).
  이 관절 자세가 원작의 쌍둥이 자세 자리에 들어간다(`PebbleRocky.twin`) — 원작이 쌍둥이 자세로 간 뒤 그림을 겹쳐 바꿀 때 돌멩이는 관절이 곧장 그 자세로 섞여 간다.
  잠들 땐 다리를 몸 안으로 올려 넣으며 내려앉고(바닥을 뚫지 않게) 원작이 잠 그림을 겹치는 동안 팔다리가 옅어진다. 표정은 선이라 겹쳐 바꾸지 않고 절반에서 바꾼다.
  구르기는 토막의 75% 에 한 바퀴를 다 돌고 0도로 적는다 — 끝의 섞는 시간에 360도에서 0도로 섞으며 거꾸로 되돌아 돌지 않게.
  비밀번호를 칠 때 눈 가리기(`RockyPose.coverEyes`)도 같은 자세를 받아 팔을 몸 앞에 그린다 — 어깨만 안쪽으로 옮겨 손이 돌멩이의 눈 자리에 오게 맞췄다.
  돌멩이에만 있는 쉬는 동작이 여덟 개 더 있다(같은 날 오너 "그냥 다 넣자") — 구르기 · 몸 털기 · 기지개 · 춤(음표) · 돌인 척하기(팔다리를 넣고 한쪽 눈만 뜬다) · 하품 · 박수 · 하트.
  `Move.isExtra` 이고, 앱은 그림체가 돌멩이면 `Choreographer.extras` 를 켠다. 원작 조각은 돌리기만 해서 구르기나 돌인 척이 어색하므로 원작에는 넣지 않는다
  (그림체를 바꾸는 사이 남은 토막은 두리번(`look`)으로 대신한다). 팔다리를 넣는 자세는 `RockyPose.tuck` 이다.
  고르는 것은 메뉴의 "모양"(원작 · 돌멩이)이나 오른쪽 클릭 메뉴, `defaults` 의 `avatarStyle`(`concept` · `pebble`, 모르는 값은 원작 — `RockyKit.AvatarStyle`).
  같은 날 도형으로 그린 미니멀 벡터와 셋을 나란히 띄우는 "모두"도 잠깐 있었지만 오너가 원작과 돌멩이 둘만 남기기로 했다 — 옛 값(`minimal` · `all`)은 원작으로 읽힌다.
  메뉴의 토글이나 아바타의 오른쪽 클릭으로 끈다(`defaults` 의 `avatar`). 자리는 돌아다니기를 끈 동안만 패널이 기억한다(`RockyAvatar`).
- **돌아다니기**(`defaults` 의 `roam`, 기본 켜짐) — 일하는 중이면 창 윗면을 걷고, 바닥에 오래 머물지 않는다(오너 요청 2026-10-29 — 바닥에만 붙어 있었다).
  앞을 막은 창 옆면은 너머 윗면에 설 자리가 있을 때만 넘는다 — `jumpReach`(260pt) 안이면 70% 로 쪼그렸다가 뛰어오르고, 더 높거나 안 뛰면 50% 로 튜브를 놓아 넘어가고, 아니면 돌아선다.
  옆면은 몸 가운데가 아직 그 앞이고 다음 걸음의 앞쪽 끝이 닿으면 막는다 — 윗면 끝에서 뛰어내리면 몸 가운데가 끝을 막 지난 자리에 내려앉아 몸 절반이 옆면 안쪽에 걸치는데,
  앞쪽 끝이 옆면을 지나는 순간만 보면 걸친 로키는 바닥에 선 창 앞을 그냥 지나갔다(2026-11-09 실측). 걸친 채 뛰어오를 때는 바깥으로 물러나지 않고 그 자리에서 쪼그린다.
  발판 끝에서는 `hopGap`(160pt) 안의 건너편 발판(위아래 260pt 안)으로 70% 로 건너뛰고, 건너뛸 데가 없으면 `dropChance`(30%)로 뛰어내리고 나머지는 돌아선다.
  화면 가장자리에서는 돌아선다(기어오르기는 2026-10-29 오너 결정으로 뺐다). 뛰는 중에 내려설 발판이 사라지거나, 밟던 창이 사라지거나 옮겨 가면 떨어진다.
  누르고 있는 동안은 걷지 않고 포인터에 매달려 있다가(누른 채 멈춰 있어도) 놓으면 그 자리에서 떨어진다. 깨어 있으면 일하는 중처럼 돌고, 내 차례면 서 있다 가끔 서성이고(따라다니기),
  연결 없음이면 서 있고, 다 쉬면 앉는다.
  헤일메리의 터널처럼 반투명 튜브를 놓아 건너가기도 한다 — 바닥에서 올라갈 창 윗면이 있으면 걷는 동안 초당 15%(`upRate`)로 그중 하나로 오르고,
  창 위에서는 초당 4%(`tubeRate`)로 150pt 넘게 떨어진 다른 창 윗면으로 건너간다(창 위에서 바닥으로는 떨어져서만 내려온다). 설 창 윗면이 없는 바닥(창이 다 큰 화면)이면
  초당 4% 로 300pt(`crossing`) 넘게 먼 바닥으로 화면 높이의 30-60%(`crossingRise`) 만큼 솟는 튜브를 놓는다. 관은 로키 패널 바로 뒤의 클릭을 흘려보내는 패널에 그리고,
  로키는 관 안에서 0.45배로 줄어든다. 튜브는 한 번에 하나, 건너는 중엔 기분이 바뀌어도 마저 건너고, 끌어다 놓으면 관이 사라진다.
  비율을 바꾸면 바닥에 머무는 시간을 다시 잰다 — 레포 밖 프로젝트 파일 `mac-avatar/roam/`의 `roam.py`(`Roamer` 의 Python 사본)와 `sim.py`(창 배치 셋, 25초마다 창 전환)로
  2026-10-29 에 잰 값은 바닥에 있는 시간이 창이 섞인 화면 35%(전 63%), 작은 창들 13%(전 50%), 다 큰 창 90%(전 100%)다.
  판정(발판·벽·한 걸음·빠르기)은 `RockyKit` 의 `Roamer`, 발 디딤은 `Feet` 순수 함수이고, 앱은 걸음을 재고 패널을 옮기고 그리기만 한다. 박자는 패널 화면의 디스플레이 링크(`NSView.displayLink`, 30-60fps, 120Hz 화면에서도 60)이고
  로키 그림(`TimelineView`)도 같은 60이다 — `Timer` 로 초당 30번 옮기던 때는 화면 주사율과 어긋나 패널이 들쭉날쭉 멈춰 프레임 드랍처럼 보였다(2026-11-06).
  둘 중 하나만 낮추지 않는다. 아무도 못 보면 둘 다 멈춘다(판정은 `RockyKit.framesRun`) — 화면이 잠들었거나(`NSWorkspace.screensDidSleepNotification`) 화면이 하나도 없거나
  패널이 화면 안에서 다 가려지면(`occlusionState`, 화면 잠금 · 화면 보호기 포함). 화면 밖으로 밀려난 패널(화면을 뺐을 때)은 돌아다니는 동안은 돌린다 — 박자가 돌아야 화면 안으로 걸어 들어온다.
  알림은 바뀔 때만 오므로 패널이 뜰 때, 화면이 붙거나 빠질 때(`didChangeScreenParametersNotification`), 돌아다니기를 켜고 끌 때도 다시 잰다 — 처음부터 안 보이던 패널은 알림이 오지 않는다.
  화면 없는 맥(Mac Studio)도 AppKit 에는 가상 화면 하나(3008×1692)로 보이고 패널도 보이는 것으로 판정돼 멈추지 않는다 — 거기서 보는 사람 없이 CPU 4.5-5.8% 를 썼다
  (2026-11-06 실측, `screencapture` 는 실패한다). 화면이 잠들거나 가려질 때 실제로 멈추는지는 화면 있는 맥에서 아직 재지 못했다. 다시 보이면 멈췄던 동안을 한 걸음으로 치지 않는다. 창 목록은 `CGWindowListCopyWindowInfo` 로 0.5초마다 위치만 읽는다(처음 한 번만 기다리고, 그 뒤엔 메인 스레드 밖에서 —
  창이 많으면 수십 ms 걸려 걸음이 멈칫했다) — 창 이름을 읽지 않으니 화면 기록 권한을 묻지 않는다. 패널은 로키 칸(말풍선이 떠 있는 동안은 패널 전체) 위에 마우스가 있을 때만 클릭을 받고, 나머지는 아래 창으로 흘려보낸다(`ignoresMouseEvents`).
- **로그인할 때 뜬다**(오너 요청 2026-11-06 — 데몬은 launchd 로 로그인 때 뜨는데 앱은 사람이 열어야 했다). 앱이 macOS 로그인 항목
  (`SMAppService.mainApp`, `LoginItem.swift`)에 스스로 오른다 — .app 으로 처음 뜰 때 한 번만 저절로 올리고(`defaults` 의 `loginItemOffered`),
  그 뒤에 메뉴의 "로그인할 때 열기"나 시스템 설정 > 일반 > 로그인 항목에서 끈 것은 되살리지 않는다. 데몬·훅·`rocky daemon install` 은 앱을 띄우지 않는다 —
  앱은 데몬의 클라이언트라 둘 중 누가 먼저 떠도 SSE 가 다시 붙는다. `swift run` 의 실행 파일은 올릴 수 없어 토글을 숨긴다.
- **따라다니기**(`defaults` 의 `follow`, 기본 켜짐, 돌아다니기가 켜져 있을 때만) — 사람이 보는 곳 옆으로 간다(오너 요청 2026-11-06 — 창 · 포인터 · 활동을 따라다니게).
  눈길(`GazeTracker`)은 포인터가 0.6초 멈춘 자리, 키 입력이 3초 안이고 포인터보다 나중이면 앞 앱의 맨 앞 창 윗변(포인터가 그 창 위면 포인터 x, 아니면 창 가운데)이다.
  거슬리지 않게 하는 장치가 셋이다 — 움직이는 포인터는 따라가지 않고, 180pt 안쪽으로 옮긴 것은 무시하며, 로키 발 160pt 안의 포인터(로키를 누르려는 손)는 눈길로 치지 않는다.
  입력이 120초 넘게 없으면 눈길을 놓고 평소처럼 돈다. 설 자리(`followGoal`)는 눈길 바로 아래가 아니라 옆으로 110pt 비켜선, 눈길보다 낮은 발판 중 가장 높은 곳(양쪽 중 더 높은 쪽, 같으면 로키가 있는 쪽)이다.
  `Roamer` 는 내 차례(`pace`)면 60pt 안까지 다가가 서서(말풍선이 눈길 곁에 뜬다) 기다리다, 3초(`paceRest`) 넘게 서 있으면 초당 20%(`paceRate`)로 그 60pt 안의 다른 자리
  (같은 발판, 지금 자리에서 30pt 넘게, 창 옆면에 막히지 않는 곳)로 몇 걸음 옮긴다 — 제자리에서 튀기만 했다(2026-11-06 오너 지적). 크게 알리거나 손을 흔드는 동안은 서성이지 않는다
  (`stay` — 걷다가도 멈춘다). 연결 없음도 `stay` 다. 일하는 중·깨어 있음(`roam`)이면 220pt 목줄 안에서 평소처럼 돌되 다른 창으로 건너가는 튜브는 놓지 않는다. 다 쉬면 보지 않는다.
  다른 발판이거나 같은 발판이라도 400pt 넘게 멀면 튜브로 가는데, 초당 확률(내 차례 100%, 일하는 중 50%)로 놓고 한 번 놓으면 6초 동안은 다시 놓지 않는다. 창 옆면에 막히면 튜브로 넘거나 서서 그쪽을 본다.
  신호는 권한 없이 읽는다 — 포인터 자리 `NSEvent.mouseLocation`, 마지막 입력 뒤 흐른 초 `CGEventSource.secondsSinceLastEventType`(이동 · 끌기 · 스크롤 · 누름, 키), 앞 창은
  `NSWorkspace.frontmostApplication` 의 pid 로 이미 읽은 창 목록에서 찾는다(창 이름 · 접근성 API 를 쓰지 않는다). 키 입력 시계를 못 읽으면 앞 창은 안 보고 포인터만 본다. 0.1초마다 다시 본다.
  레포 밖 `mac-avatar/roam/roam.py` 는 따라다니기를 흉내 내지 않는다 — 눈길이 없을 때(`goal` nil)의 비율은 그대로라 바닥 시간 측정은 유효하다.
  가속·감속(`walkAccel`, 2026-11-06)도 아직 흉내 내지 않는다.

  `codesign` 하고, 없으면 ad-hoc(`-`)으로 서명한다. 오너의 맥은 자체 서명 인증서 `rocky` 를 쓴다(2026-10-27):
  `ROCKY_MAC_SIGN_IDENTITY=rocky mac/scripts/bundle.sh`. 서명 안 된·ad-hoc 빌드는 해시가 빌드마다 바뀌어 회사 맥 EDR 이 의심할 수 있다 — 그 맥에는

  (`rocky_cli::mac_app`, 판정은 `rocky_core::mac_app`). 자리는 이미 깔린 곳(`/Applications` 먼저, 다음 `~/Applications`), 없으면 쓸 수 있는
  `/Applications`, 아니면 `~/Applications`. 버전(`CFBundleVersion`)이 같으면 두고, nightly 는 앱 버전이 `package.json` 그대로라 새로 받았을 때만 버전을 보지 않고 바꾼다.
  키체인에 인증서가 있으면 **그 기기에서 다시 서명**한다 — `ROCKY_MAC_SIGN_IDENTITY` 가 있으면 그것(`-` 면 CI 의 ad-hoc 그대로), 없으면
  `security find-identity -p codesigning` 에 `"rocky"` 가 있을 때만 `rocky`. 같은 폴더의 `.Rocky.app.new` 에 복사 → 격리 속성 지우기 → 서명 → `codesign --verify --strict`
  를 다 통과한 뒤에야 rename 으로 바꿔 끼우고, 하나라도 실패하면 깔린 앱을 그대로 둔다. 돌고 있던 앱은 SIGTERM(`pkill -f`)으로 내렸다가 다시 띄우고
  (AppleScript `quit` 은 자동화 권한 창을 띄워 쓰지 않는다), 처음 깐 앱은 띄우고, 깔려 있는데 꺼져 있던 앱은 사람이 끈 것이라 띄우지 않는다.
  맥 앱 실패는 경고(`⚠`)로만 남기고 바이너리·데몬 업데이트를 되돌리지 않는다. CI 에서 앱 빌드가 깨지면(`continue-on-error`) 앱 없이 낸다 — 바이너리 릴리스를 막지 않는다.
  앱이 없는 tarball(이 변경 전 릴리스)이면 아무것도 하지 않는다. 플러그인 자동 업데이트(SessionStart 부트스트랩)는 앱을 깔지 않는다 — 훅에서 앱을 내리고 띄우지 않는다.

## 함정

- **Linux 컨테이너에는 Swift 가 없다**(클라우드 세션의 네트워크 정책이 swift.org 를 막는다). 빌드 확인은 CI 의 macOS 러너나 오너의 맥에서 한다.
- **화면(SwiftUI)은 테스트가 못 본다** — 메뉴 막대·창을 바꾸면 맥에서 한 번 띄워 본다(`swift run --package-path mac RockyMac`).
  기본 포트(8636)는 실제 보드다 — 착수·완료·추가 버튼은 실제 보드를 바꾼다.
- `LSUIElement` 앱이라 평소엔 Dock 아이콘이 없다. 할 일 창이 떠 있는 동안만 `setActivationPolicy(.regular)` 로 Dock·⌘Tab 에 보이고, 닫으면 `.accessory` 로 돌아간다.
  창을 열 때 `NSApp.activate` 를 먼저 불러야 창이 앞으로 온다. 앱 아이콘은 `mac/AppIcon.icns`(아바타를 그린 것)를 `bundle.sh` 가 넣는다.
- `rocky update --main` 은 맥 앱을 빌드하지 않는다 — main 빌드 기기는 `mac/scripts/bundle.sh` 로 따로 만든다(릴리스·nightly 만 tarball 에서 깐다).
