# 핸드오프 세션을 rc 로 띄우기 — 실행 계획

> **날짜**: 2026-10-06 · **보드**: rocky-41(겹침: rocky-53 — 할 일 상세의 "에이전트에게 보내기" 확장) ·
> **기대는 것**: rc 이관(rocky-28)의 기동기 — 새 프로세스 그룹으로 띄우고 놓기, 기동 로그로 등록 판정

보드에서 "새 세션 띄우기"(spawn)를 누르면 데몬이 그 할 일의 워크트리에서 `claude rc` 서버를 띄우고, 서버가 미리 만든
세션에 **데몬이 받은편지함 소켓으로** 작업 요청을 넣는다. 사람은 버튼만 누른다. 지금의 `claude --bg` 세션은 로그인 세션
밖에서 돌아 ssh · 자격이 끊긴다 — PR 로 끝나는 일을 끝낼 수 없다(2026-09-04 · 2026-10-05 실측). rc 서버가 띄운 세션은 정상이고
폰 · 웹에서도 보인다.

## 잰 것 (2026-10-06, Claude Code 2.1.288 · 2.1.289)

| 질문 | 결과 | 근거 |
|---|---|---|
| 1. 새 세션이 **첫 턴 전에** 받은편지함을 등록하나 | **한다** — 지금 코드 그대로 | SessionStart 훅 env 에 `CLAUDE_CODE_MESSAGING_SOCKET` 이 있다(`claude -p` 에 SessionStart · UserPromptSubmit 훅을 걸어 env 를 떠 봄 — 같은 소켓). rocky 의 SessionStart(`startup`) 훅이 이미 `register_inbox` 를 부른다(`crates/rocky-cli/src/hooks.rs`). rc 서버가 미리 만든 세션은 첫 메시지 전에 SessionStart:startup 이 돈다(mdwire 세션 기록: 훅 22:56:14Z, 첫 메시지 22:57:13Z) |
| 2. 서버를 띄운 뒤 세션이 뜨기까지 | 세션 프로세스 · 소켓 **3~5초**, SessionStart 훅 **6~7초** | mdwire 서버 07:56:08 → 세션 07:56:11(소켓 같은 초), cc-usage 08:34:12 → 08:34:16 → 훅 08:34:19 |
| 3. 넣은 메시지가 승인 대기에 걸리지 않는 조건 | 세션의 권한 모드가 **auto** 면 바로 턴을 연다 | 세션은 설정의 기본 모드로 뜬다(이 기기 `defaultMode: auto` · 데몬은 `--permission-mode` 를 넘기지 않는다). 이 계획을 쓴 세션이 rc 서버의 auto 세션이고, 데몬이 소켓으로 넣은 머지 후보 · 리뷰 알림을 승인 없이 처리했다. bypass 모드는 승인 창을 띄우고 보류한다(2026-09-29 실측, `docs/board.md`). default · acceptEdits 는 안 쟀다 |

곁에서 안 것:

- **도는 서버에 새 세션을 로컬에서 청하는 방법은 없다.** `--spawn worktree` 는 claude.ai 에서 여는 세션에만 워크트리를 주고, 미리
  만드는 세션은 서버의 현재 폴더에 남는다(공식 문서 "Remote Control"). 그래서 **데몬이 워크트리를 먼저 만들고 그 안에서 서버를
  띄운다.**
- `-c` 로 이어받은 세션은 SessionStart 가 `resume` 이라 rocky 훅(matcher `startup`)이 돌지 않는다 — 첫 턴까지 등록이 없다.
  핸드오프는 새 세션이라 상관없다.
- `claude remote-control --help` 는 계정 자격을 확인한 뒤에야 도움말을 낸다(문서). 이 기기에서 2분 동안 아무것도 내지 않아 그
  pid 만 내렸다 — 플래그는 공식 문서로 확인했다.

## 흐름

1. **라우트** — `POST /api/todos/:ref/spawn` 그대로(로컬 전용, 순서 계약 유지). 이 기기에서 `rc` 가 켜져 있으면 rc 경로, 꺼져 있으면
   지금의 `claude --bg`(rc 를 못 쓰는 기기) — 그 결과에는 "PR 로 끝나는 일은 끝내지 못할 수 있다" 경고를 단다.
2. **워크트리** — `<보드 경로>/.claude/worktrees/todo-<n>` 이 있으면 정말 git 워크트리인지(`rev-parse --show-toplevel`) 보고 쓰고,
   없으면 데몬이 `git fetch origin <기본 브랜치>`(짧은 한도 — 실패해도 진행) 뒤 `git worktree add -b worktree-todo-<n> <경로>
   origin/<기본 브랜치>`(기준은 `origin/HEAD` → `origin/main` → `origin/master`, 만들다 실패하면 반쯤 만든 것을 걷는다). Claude Code `--worktree todo-<n>` 과
   **같은 자리 · 같은 브랜치 이름**이라 지금까지 spawn 으로 만든 워크트리와 이어진다. 차이: 손으로 만든 워크트리는 Claude Code 의
   정리 sweep 이 지우지 않고, `.worktreeinclude` 는 처리되지 않는다(Claude Code 만 한다).
3. **서버** — 그 워크트리에서 `claude rc --spawn session --name=<보드>-<n>: <요약>`(단일 세션 모드 — 세션 하나만, 다른 접속은 거절).
   기동은 rc 기동기와 같게: 새 프로세스 그룹으로 띄우고 놓는다, 로그 `<todo dir>/rc/handoff-<보드>-<n>.out` · `.err`(보드 key 는 파일
   이름에 안전한 글자로), 등록은 `· Connected ·` 로 판정. `already served` 는 다시 해 보지 않는다 — 요청이 몇 분씩 붙잡히지 않게
   그 서버를 내리고 "3분쯤 뒤 다시" 를 알린다.
4. **세션 찾기** — 받은편지함 등록 중 **소켓 이름의 pid 의 부모가 그 서버 pid** 이고 서버를 띄운 뒤에 등록한 것(`ps` 한 번). 60초까지
   기다린다. cwd 는 보지 않는다(부모 pid 로 충분하고, 경로 표기가 갈리면 놓친다).
5. **넣기** — 그 세션 id 로 대기 중 핸드오프(`create_handoff` — 핸드오프 라우트와 같은 기록)를 만들고, 소켓에 핸드오프 poke(핸드오프
   라우트와 같은 문구 — 늘리지 않는다)를 한 줄 쓴다. 턴이 열리면 훅이 그 핸드오프를 집어 전체 지시를 넣고, 세션이 `todo_status start`
   로 착수하면 지금 규칙대로 귀속된다.
6. **이미 있으면** — 그 워크트리에 살아 있는 세션이 있으면 띄우지 않고 그 세션에 핸드오프(지금 규칙 그대로).

## 경계

- **rc 감시 · 야간과 섞이지 않는다** — 핸드오프 서버는 `rc` 대상이 아니라 감시가 되살리지 않고 야간이 다시 띄우지 않는다. 지금
  현황에서는 "목록에 없는 폴더의 서버(strays)"로 보인다 → b 에서 따로 보인다.
- **로컬 전용** — 프로세스를 띄운다.
- **실패** — 워크트리 생성 실패 · 서버 등록 실패 · 60초 안에 세션 등록 없음이면 배달 기록을 남기지 않고 400 + 사유. 서버는 떴는데
  세션만 못 찾았으면 서버는 남긴다(사람이 폰에서 열 수 있다) — 사유에 서버 이름을 적는다.

## 정한 것 (오너, 2026-10-06)

1. **spawn 을 rc 로 바꾼다**(의도한 것) — 버튼 · 명령은 하나. rc 가 꺼진 기기(`rc` 블록이 없거나 꺼짐)는 rc 를 쓸 수 없으니 지금의
   `--bg` 에 경고를 달아 둔다.
2. **서버 이름** — `<보드>-<n>: <요약>`(예: "rocky-41: 핸드오프 작업"). 요약은 할 일 제목 앞 24글자 — 데몬은 요약을 지어낼 수 없어
   제목을 띄어쓰기에서 자른다.
3. **내리기** — 세션이 끝났다고 알려 오면 오너가 닫는다. 자동으로 내리지 않는다.
4. **동시 상한** — 할 일당 하나.
5. **rocky-53** 을 여기로 합쳤다 — b 조각.

## 첫 실제 핸드오프에서 볼 것 (서버를 띄우는 일이라 그때 승인 받고)

- `.claude/worktrees/` 아래 새 워크트리에서 `claude rc --spawn session` 이 **작업 공간 신뢰를 묻지 않고** 뜨나 — 신뢰 기록
  (`~/.claude.json`)에 워크트리 경로는 따로 없고 레포 루트만 있다. 레포 루트 아래라 물려받을 것으로 본다(미확인).
- `--spawn session` 서버의 미리 만든 세션이 그 "하나" 인가, 그 모드도 `· Connected ·` 를 내나(안 내면 등록 판정에서 40초를 더 기다린다).
- `--name=<이름>` 꼴을 받나(한 인자로 넘겨 보드 key 가 `-` 로 시작해도 플래그로 읽히지 않게 했다).
- SessionStart 직후 넣은 poke 로 첫 턴이 열리고, 그 메시지가 폰 · 웹에서도 보이나.
- (이미 잰 것) 세션 프로세스는 서버의 자식이고 소켓 이름이 그 pid 다 — mdwire 세션 45995 의 부모 45932 · `45995.sock`. rc 세션은
  `claude agents` 목록에 cwd 와 함께 나온다(`/api/sessions`).
