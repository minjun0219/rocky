# rc 서버 관리 5조각 — 확인 관문 · 옛 CLI 은퇴 실행 계획

> **날짜**: 2026-10-06 · **보드**: rocky-28 · **설계**: `docs/design/specs/2026-10-05-rc-server-design.md` ·
> **앞 조각**: 1조각(현황) · 2조각(띄우기 · 재시작) · 3조각(감시) · 4조각(야간 재시작, #372~#377) 머지

5조각은 코드보다 운영이 크다. 세 갈래다. **진행(2026-10-06)**: A 의 확인 규칙과 C 의 1~3(배포 · 실측 · 컷오버)은 끝났다 —
지금은 C 4(2주 관찰, ~10-20)와 B 구현이 남았다. B 는 오너 결정("모두 옮겨와")으로 옛 기능을 빼지 않고 전부 가져온다.

- **A. 확인 관문** — 에이전트가 서버를 바꾸는 `rocky rc` 를 부를 때 사람 확인을 받는다(설계 8절 3번 결정 (b)).
- **B. 은퇴 전에 메울 표면** — 옛 CLI 에만 있고, 그 CLI 를 부르는 쪽(다른 레포의 커맨드 · 스킬)이 기대는 것.
- **C. 은퇴 절차** — 실측 → 컷오버 → 2주 관찰 → 옛 CLI 걷기. 다른 레포가 소유한 머신 설정이 섞여 그쪽과 날을 맞춘다.

## A. 확인 관문

**끝남(2026-10-06)** — 아래 규칙을 사용자 설정에 넣었다(백업 `settings.json.bak-20261006105945`). 은퇴 때 다른 레포의 설치
스크립트가 훅 대신 이 규칙을 끼우게 바꾸는 일이 남았다.

**넣기 전의 빈자리**: `rocky rc start|restart|nightly` · `rocky rc agy start|stop` 이 이미 머지돼 있는데, 사용자 설정
(`~/.claude/settings.json`)의 `permissions.ask` 에는 이것들이 없다. 걸려 있는 것은 옛 CLI 의 PreToolUse 훅
(`rc-up --hook-ask`)뿐이라, 지금은 에이전트가 rocky 쪽 손잡이를 확인 없이 부를 수 있다.

**넣을 규칙**(결정 (b) — 코드 0줄):

```json
"ask": [
  "Bash(rocky rc start:*)", "Bash(rocky rc restart:*)", "Bash(rocky rc nightly:*)",
  "Bash(rocky rc agy start:*)", "Bash(rocky rc agy stop:*)"
]
```

- `rocky rc nightly:*` 는 판정만 하는 `--dry-run` 까지 묻는다 — 접두어 규칙이라 둘을 가르지 못한다. 묻는 쪽이 안전하다.
- `sh -c` 같은 래퍼와 `curl` 로 데몬을 직접 부르면 비켜 간다 — 설계에서 받아들인 한계다(옛 훅의 렉서 400줄은 이
  우회를 막으려던 것). 데몬 라우트가 로컬 전용이라 노출된 화면에서는 어차피 막힌다.
- **누가 넣나**: 그 파일의 rc 훅 항목은 다른 레포의 설치 스크립트가 끼운다(`RC_HOOK_CMD`). 은퇴 때 그 스크립트가 훅
  대신 이 규칙을 끼우게 하는 것이 정본이고, 그 전에는 오너가 손으로 넣는다. rocky 는 README 에 권장 규칙을 적는다.

## B. 옛 CLI 에만 있는 것 — 가져올지

옛 CLI 를 부르는 쪽(다른 레포의 `/rc-up` 커맨드 · `remote-control` 스킬)이 실제로 쓰는 호출은 `<이름>`(열기) · `-s`(현황,
커맨드가 첫머리에 자동 실행) · `-r [--fresh]` · `--nightly -n` · `--log` 다(2026-10-06 그쪽 세션 확인).

| 옛 기능 | 누가 기대나 | 제안 |
|---|---|---|
| `-s` 의 **최근 활동** — 대상마다 정박/닫힘, 마지막 커밋 시각 · 제목, `*작업중`(dirty), `@브랜치` | `/rc-up` 커맨드가 "뭘 열 수 있나" 를 고를 때 | **가져온다** — `rocky rc --activity`. 꺼진 대상마다 `git` 을 몇 번 돌리므로 5초 폴링 현황에는 넣지 않고, 부를 때만 잰다(`GET /api/rc/servers?activity=1`) |
| **낮 재시작의 턴 대기** — 열린 세션이 2분 안에 대화했으면 15초마다 보며 10분까지 기다린다 | 사람이 부른 재시작 · 자기 서버 재시작 | **가져온다** — 행 상태에 "대화가 끝나길 기다리는 중". 자기 서버를 재시작해도 그 턴이 끝난 뒤에 내려간다(아래 자가-살해 항목) |
| `--log` — 최근 실행 기록, 야간 보고(설치 버전 · 서버별 이전→이후 · 건너뛴 이유) | 그쪽 세션이 채팅으로 새벽 결과를 전한다. `logs` 명령 · lnav 포맷이 그 파일을 연다 | **`rocky rc nightly --last`** — 마지막 야간 보고를 리허설과 같은 모양으로. 원본 기록은 `<todo dir>/rc/events.jsonl`(경로를 README 에 적는다 — lnav 포맷은 그쪽이 맞춘다) |
| 야간의 rocky 버전 기록(플러그인 · CLI · 데몬과 최신 태그) | 같은 채팅 보고 | **가져온다** — 야간 보고에 rocky 세 층의 버전과 최신 릴리스 태그를 싣는다(설치는 하지 않는다 — 기록만). 태그는 네트워크를 타니 몇 번 다시 본다 |
| `-a`(비고정 일괄, 비상용) | 커맨드 힌트 | **가져온다** — `rocky rc start --all`: 꺼진 대상 전부를 서버만으로(세션을 만들지 않는다) |
| `--session-id`(이어받을 세션 못 박기) | 지금 절차에서 안 씀 | **가져온다** — `rocky rc restart <라벨> --session <cse_… · session_…>` → `claude rc --name <라벨> --session-id <id>`. 형식이 틀리면 거른다. 이어받기처럼 안 뜰 수 있어 안 뜨면 새로 한 번 더 |
| 낮 재시작의 `already served` 간격(45 · 90초) | — | **늘린다**(실측 2026-10-06: cc-plugins 재시작이 세 번 모두 served 로 실패하고 3분 뒤 풀렸다) — 60 · 120초(합 3분). 옛 CLI 도 같은 값이라 같은 일을 겪었다 |
| 자가-살해 가드(설계 6절 1번 — "CLI 경로의 ppid 사슬 검사는 남긴다") | — | **가져온다** — CLI 가 자기 조상 사슬에 그 서버 pid 가 있으면 거절한다. (처음엔 턴 대기로 대신하려 했으나, 턴 대기는 대화 기록이 2분 조용하면 끝난 것으로 보므로 2분 넘는 도구 호출 — `--wait` 로 부른 이 명령 자신 포함 — 을 못 본다. 프리리뷰에서 실측으로 짚었다) |

## C. 은퇴 절차 (운영)

1~3 은 2026-10-06 에 했다 — 160ae53 배포, 리허설 맞대기(차이는 대상 밖 서버 · canary 순서뿐), 비고정 재시작(백오프 부족 발견 → 3분
뒤 복구), 기록 24개 · `auth.json` 이관, `supervise` · `nightly` 켜기(감시 첫 바퀴 11:00:44 KST), 다른 레포가 옛 잡 둘을 걷음.

1. **배포 확인** — 메인 세션의 main-sync 뒤 운영 데몬에 리허설 라우트가 있는지(`GET /api/rc/nightly/preview` 가 404 가 아님).
2. **실측** — `rocky rc nightly --dry-run` 을 옛 CLI `--nightly -n` 과 맞댄다(판정만). 비고정 하나를 `rocky rc restart`
   로 실제 재시작하고 `rc/<라벨>.version` 이 남는지 본다.
3. **컷오버(같은 날 연달아)**
   - 기록 이관: `~/.config/rc-up/state/*.version` **24개 전부**(오너 "모두 옮겨와" — 대상 밖 라벨은 rocky 가 읽지 않을 뿐 해가 없다)를
     덮어쓰지 않고(`cp -n`) `<todo dir>/rc/` 로. 원본은 남긴다. `.revive` 는 지금 없다. `auth.json` 은 모양이 달라 변환한다 — 옛 `{"last_out": RFC 3339,
     "last_in": …, "manager": …}` → rocky `{"lastOut": unix 초, "lastIn": unix 초}`.
   - 사용자 `rocky.json` 의 `rc` 블록에 `"supervise": true` 와 `"nightly": {}` 를 넣고 데몬을 다시 띄운다.
   - 다른 레포 쪽: 옛 주기 · 야간 잡 끄기(그쪽 승인 · 실행).
4. **2주 관찰(조건 ④)** — `rc/events.jsonl` 의 감시 · 야간 결과를 옛 야간 잡의 동작 목록(그쪽 결정 기록의 본문과 개정 넷:
   update 선행, 버전 읽기 재시도 · 폴백, 실제 경로 네트워크 확인, canary, 되살림 표식, 07:00 까지 대기, 잠금 대기)과 맞댄다.
5. **옛 CLI 걷기(다른 레포 몫)** — 바이너리와 **같은 단계에서** 설정의 `--hook-ask` 훅 항목과 설치 스크립트의 해당
   블록(훅 끼우기 · go 빌드 · 버전 비교 · 대상 목록 배포)을 걷는다(바이너리만 지우면 훅 명령이 실패한 채 남는다). 셸 폴백,
   로그 명령의 경로 두 줄, 커맨드 · 스킬의 호출을 B 의 rocky 명령으로 바꾸고, 개발 하위 세션을 걷는다.
   `~/.config/rc-up` · `~/.local/state/rc-up` 은 보관한 뒤 지운다.

**대상 목록의 정본**: 지금 두 곳이다 — 다른 레포의 `rc-pinned` · `rc-targets`(설치 스크립트가 `~/.config/rc-up/` 으로 배포)와
사용자 `rocky.json` 의 `rc` 블록(1조각에서 같은 값으로 넣었다). **정함(오너 2026-10-06)**: `rocky.json` 하나를 정본으로 두고, 그쪽
배포는 은퇴 때 걷는다.
