# rc 서버 관리 3조각 — 감시(되살리기) 실행 계획

> **날짜**: 2026-10-06 · **보드**: rocky-28 · **설계**: [`specs/2026-10-05-rc-server-design.md`](../specs/2026-10-05-rc-server-design.md) ·
> **앞 조각**: 1조각(현황) #320 · #321 · #330, 2조각(띄우기 · 재시작) #344 · #345 · #346

3조각은 데몬이 **고정 서버가 꺼져 있으면 스스로 띄운다**. 옛 CLI 의 주기 실행(launchd 5분, `-q`)을 대신한다.
사람이 부르던 2조각의 기동기를 그대로 쓰고, 이 조각은 "언제 부르나"와 "자격이 끊겼을 때 무엇을 하나"만 더한다.

## 0. 앞 조각에서 확인된 전제

- 데몬이 띄운 서버는 데몬을 재시작 · 교체해도 산다(조건 ②, 2026-10-06 실측). 그 서버에서 `git push` 도 된다(조건 ①).
- **launchd 맥락의 claude 자격은 끊길 수 있다.** 키체인 항목이 낡으면 셸은 로그인인데 데몬만 로그아웃이 된다 — 이번에만 두
  번째였다(고친 방법은 낡은 항목을 지우고 다시 로그인). 재발 방지책이 없으니 **알아채는 장치**를 이 조각에 넣는다.

## 옛 CLI 주기 실행이 하던 것

| 하던 것 | 이 조각에서 |
|---|---|
| 고정 대상 중 꺼진 것을 세션 모드로 띄운다 | 그대로. 비고정은 띄우지 않는다(설계 6절 14번 — 비고정 자동 기동이 반복되던 함정) |
| 되살림 표식(야간이 내리고 못 띄운 것)을 서버 모드로 띄운다 | **4조각으로 미룬다** — 표식을 만드는 쪽이 야간 재시작이다 |
| 자격이 확실히 로그아웃이면 아무것도 띄우지 않는다 | 그대로(2조각 기동기가 이미 거절한다). 더해 **끊김 · 회복을 한 번씩 알린다** |
| 회복을 본 첫 실행에서 "로그아웃보다 먼저 뜬 서버" 를 한 번 경고한다(자격 의심 — 그 서버는 죽은 토큰을 들고 있다) | 그대로. 현황 행에 `authSuspect`, 알림 한 번. 자동 재시작은 하지 않는다 |
| 잠금(`mkdir`) — 겹친 실행은 건너뛴다 | 대상별 진행 표시(2조각)가 대신한다 — 사람이 재시작 중인 대상은 건너뛴다 |
| 5분 간격 | 2분 간격(`ps` · `lsof` · `claude auth status` 가 한 번 — 옛 CLI 는 launchd 기동 비용 때문에 5분이었다) |

## 판정 (`rocky_core::rc`, 순수)

- `revive_targets(status) -> Vec<label>` — 고정이면서 꺼졌고, 진행 중이 아니고, 프로브가 성공했고, 자격이 로그아웃이 아닌 대상.
- **연속 실패 쉬기**: 같은 대상이 연달아 못 뜨면 2 · 4 · 8 · 16 · 30분(상한) 쉬었다 다시 — 폴더가 사라졌거나 trust 가 풀린 대상을
  2분마다 두드리지 않게. 한 번 뜨면 처음으로.
- **자격 관찰** `next_auth_mark(state, mark, now) -> (mark, Transition)` — 옛 `NextAuthMark` 를 옮긴다. `Out` 을 보면
  `last_out = now`, 그 뒤 처음 `In` 을 보면 `last_in = now` 이고 `Recovered`. `Unknown` 은 기록을 건드리지 않는다.
- `auth_suspect(server_uptime, mark, now)` — 회복한 뒤, 기동 시각이 `last_out` 보다 앞선 서버.

## 배선 (`rockyd::rc`)

- `spawn_rc_supervisor` — `spawn_sweeper` 와 같은 모양(`tokio::spawn` + sleep 루프). 기동 2분 뒤 처음, 그 뒤 2분마다.
  **`rc.supervise: true` 일 때만** 띄운다(기본 꺼짐 — 옛 주기 잡과 동시에 서버를 띄우지 않게).
- 한 바퀴: 캐시 없이 프로브 → 자격 관찰 갱신 → `revive_targets` 마다 2조각 기동기에 `Start` 를 맡긴다(대상마다 `begin` →
  `run`, 겹친 대상은 `Busy` 로 자연히 건너뛴다). 이벤트는 같은 `rc/events.jsonl` 에 `supervise` 로.
- **알림**: 자격이 `In → Out` 으로 바뀐 바퀴에 한 번, `Out → In`(회복)에 한 번 macOS 배너(검증 알림과 같은 `osascript`).
  로그아웃 배너는 고칠 곳을 말한다 — "launchd 맥락 claude 자격이 끊겼다 — 고정 서버를 되살리지 못한다".
- 자격 관찰 기록(`last_out` · `last_in`)은 `<todo dir>/rc/auth.json` 에 둔다 — 데몬을 다시 띄워도 회복을 알아채게.
- 현황에 `supervise`(켜졌나 · 마지막 바퀴 시각)와 행마다 `authSuspect` 를 싣는다.

## 설정

```jsonc
"rc": { "enabled": true, "supervise": true, "pinned": [...], "targets": [...] }
```

`supervise` 는 `rocky.schema.json` + `config.rs` 를 함께(변경 체크리스트 5).

## 웹 (작게)

- 요약 줄: 감시가 켜져 있으면 `감시 중` 글자. 자격이 로그아웃이면 그 사실을 `mine` 으로(지금은 `auth` 를 환경 줄에만 보인다).
- 행: `authSuspect` 면 "자격 의심 — 다시 띄우기를 권한다" 한 줄(재시작 버튼은 2조각 것).

## 넘어가기(컷오버) — 코드가 아니라 운영

이 조각이 머지된 뒤 이 맥에서 한 번:

1. 사용자 `rocky.json` 에 `rc` 블록(고정 · 대상 목록 — 옛 CLI 의 목록 그대로)과 `supervise: true` 를 넣는다.
2. **옛 주기 잡을 끈다** — 그 잡은 다른 레포가 소유한 머신 설정이라, 끄는 결정과 실행은 그쪽과 맞춘다. 끄기 전에 둘이 동시에
   켜지지 않게 순서를 지킨다(rocky 쪽 `supervise` 를 켜는 것과 옛 잡을 끄는 것을 같은 날 연달아).
3. 며칠 `events.jsonl` 과 옛 CLI 로그를 맞대 본다(이관 조건 ④). 야간 잡(04:30)은 4조각까지 옛 CLI 가 계속 돈다.

## 하지 않는 것(이 조각)

- 되살림 표식 · 야간 재시작 · `claude update` — 4조각.
- 자격 의심 서버의 자동 재시작 — 옛 CLI 도 하지 않았다(그 서버에 세션이 붙어 있을 수 있다).
- 비고정 서버 자동 기동.

## 확인

1. 게이트 6개.
2. 가짜 프로세스 세계로: 고정이 꺼지면 한 바퀴에 띄운다 · 비고정은 안 띄운다 · 진행 중이면 건너뛴다 · 연속 실패 쉬기 · 자격 `Out`
   이면 아무것도 안 띄우고 배너 한 번(같은 상태가 이어지면 다시 안 울림) · 회복하면 배너 한 번과 자격 의심 표시.
3. 실측: 컷오버 뒤 고정 서버 하나를 pid 로 내려 2분 안에 되살아나는지.
