# rc 서버 관리 4조각 — 야간 재시작 · 되살림 실행 계획

> **날짜**: 2026-10-06 · **보드**: rocky-28 · **설계**: `docs/design/specs/2026-10-05-rc-server-design.md` ·
> **앞 조각**: 1조각(현황) · 2조각(띄우기 · 재시작) · 3조각(감시) 머지

4조각은 옛 CLI 의 야간 잡(04:30)을 옮긴다 — `claude update` 뒤 **구버전이면서 쉬는** 서버만 재시작하고, 내렸는데 못 띄운
것은 되살림 표식을 남겨 감시가 살리게 한다. 이 조각이 끝나면 옛 주기 · 야간 잡을 **한 번에** 끈다(컷오버, 오너 결정
2026-10-06 — 주기 잡만 먼저 끄면 야간이 내린 비고정 서버를 아무도 살리지 않는 공백이 생긴다).

## 옛 야간 잡이 하던 것

| 하던 것 | 이 조각에서 |
|---|---|
| `claude update`, 뒤에 `claude --version` 을 90초까지 다시 재고 못 재면 설치 경로(`~/.local/bin/claude` 링크 대상 → `versions/` 최신)로 | 그대로 |
| 기동 때 `<라벨>.version` 에 버전 기록. 구버전 = 기록 ≠ 설치 버전. **기록이 없으면 건드리지 않는다** | 그대로. 기록은 `<todo dir>/rc/<라벨>.version` — 2조각 기동기가 띄울 때마다 쓴다 |
| 대상 = **지금 떠 있는 서버 전부**(목록에 없는 고정도) | **설정 대상 중 떠 있는 것**으로 좁힌다 — rocky 는 설정 대상만 띄우고 버전을 기록하므로 목록 밖 서버(strays)는 어차피 기록이 없다. 표식도 대상 라벨에만 남아, 옛 CLI 처럼 표식으로 대상을 넓히지 않는다 |
| 판정 순서: 버전 모름 → 기록 없음 → 최신 → 바쁨 → 네트워크 없음 → 재시작 | 자가-살해는 빠진다(데몬은 조상이 아니다) |
| 쉬는 서버 = 열린 세션이 없거나, 그 폴더 대화 기록(`~/.claude/projects/<이름>/*.jsonl`) 최신 mtime 이 60분 넘게 전 | 그대로 |
| 바쁜 서버는 5분마다 다시 보며 07:00 까지 기다린다(그동안 다른 것 먼저) | 그대로 |
| canary — 고정 하나를 먼저 내려 띄워 보고, 실패하면 나머지는 건드리지 않는다 | 그대로 |
| 내리기 **직전마다** 네트워크 확인(api.anthropic.com, IPv4, 10초 간격 3분) — 안 되면 `no-network` 로 건너뜀 | `curl -4` 로 같은 확인(새 의존성 없이) |
| `already served` 재시도 1 · 2 · 4 · 6분(낮보다 길게) | 그대로 |
| 내리기 **전에** 되살림 표식을 찍고, 뜨면 지운다(도중에 죽어도 남게). 못 뜬 것은 07:00 까지 1 · 2 · 4 · 8 · 16분 다시 | 그대로 |
| 주기 실행이 표식이 있는 **비고정**도 서버 모드로 살린다 | 3조각 감시에 더한다 — 고정 + 표식 |
| 자격 관찰 · rocky 버전 · agy 기록 | 자격은 3조각 감시와 같은 기록을 쓴다. rocky · agy 버전 기록은 옮기지 않는다 |
| 맥이 04:30 에 자고 있었으면 깬 뒤 한 번 | 그대로 — 마지막 실행 날짜를 `rc/nightly.json` 에 두고, 1분마다 "오늘 그 시각이 지났고 아직 안 돌았나" 를 본다 |

## 판정 (`rocky_core::rc`, 순수)

- `parse_claude_version("2.1.288 (Claude Code)")`, `version_from_path`, `newest_version`.
- `project_dir_name(dir)` — 영숫자가 아닌 글자를 `-` 로.
- `decide_nightly(state, now) -> NightlyDecision { reason, mode }` — 위 판정 순서. 재시작 방식은 2조각 `restart_mode`.
- `nightly_due(now_local, at, last_run_date) -> bool`, `busy_deadline(now_local, "07:00")`.
- `NIGHTLY_REGISTRATION_BACKOFF`(1 · 2 · 4 · 6분), `recovery_wait(n)`(1 · 2 · 4 · 8 · 16분).
- `revive_candidates(status, marked)` 확장 — 고정이거나 되살림 표식이 있는 꺼진 대상. 표식이 있는 비고정은 서버 모드로.
  `stale_revive_marks` — 이미 떠 있거나 설정에서 뺀 라벨의 표식(프로브가 성공했을 때만).
- `canary_first` — 고정 하나를 맨 앞에. `nightly_blocked` — 프로브 실패 · 로그아웃이면 전체를 건너뛴다.
- `nightly_first_mark` — 기록이 없을 때(처음 켠 날) 이미 돈 것으로 칠 날. 켜자마자 낮에 서버를 내리지 않는다.

## 배선 (`rockyd::rc`)

- 기동기가 띄울 때 `claude --version` 을 재 `<라벨>.version` 을 쓴다. **못 재면 지운다** — 옛 값을 남기면 새 바이너리로 뜬 서버를
  구버전으로 보고, 기록이 없으면 야간이 "모름" 으로 건드리지 않는다(옛 CLI 도 못 잰 기록을 모름으로 다뤘다).
- 되살림 표식 `rc/<라벨>.revive`(내용 = 폴더) — 야간이 쓰고, 감시가 띄워 뜨면 지운다. 이미 떠 있으면 지운다.
- `spawn_rc_nightly` — 1분마다 `nightly_due` 를 보고, 돌 차례면 한 번: update → 판정 → canary → 나머지 → 바쁨 대기 → 회복.
  사람이 부르는 띄우기 · 재시작과 같은 대상 잠금(`begin`)을 쓴다. 이벤트는 `rc/events.jsonl` 의 `nightly`.
  **회복이 끝날 때까지 못 뜬 대상의 잠금을 쥔다** — 옛 CLI 는 야간이 잠금을 쥔 동안 주기 실행이 돌지 않았다. 잠금을
  풀면 감시가 표식을 보고 같은 대상을 띄우고, 야간의 다음 회복이 그 서버를 "실패한 기동의 잔여" 로 보고 내린다.
- 끝나면 한 줄 요약을 기록하고, **canary 실패 · 끝내 못 띄운 서버가 있을 때만** 배너.
- `POST /api/rc/nightly`(로컬 전용) · `rocky rc nightly [--dry-run]` — 손으로 한 번 돌린다(실측과 비상용). `--dry-run` 은 판정만.
- 현황 행에 `stale`(구버전), 현황에 `nightly`(마지막 실행 시각 · 요약).

## 설정

```jsonc
"rc": { "supervise": true, "nightly": { "at": "04:30", "busyUntil": "07:00", "quietMinutes": 60 } }
```

`nightly` 블록이 있을 때만 돈다(기본 꺼짐). 시각은 이 기기의 현지 시각.

## 웹 (작게)

- 행에 `구버전` 글자(재시작 버튼은 2조각 것). 탭 맨 아래에 "야간: 04:30 · 마지막 06-07 04:31 — 재시작 3 · 건너뜀 2" 한 줄.

## 컷오버 — 이 조각이 머지된 뒤(운영, hail-mary 와 함께)

1. 옛 기록을 옮긴다: `~/.config/rc-up/state/<라벨>.version` → `<todo dir>/rc/` (옛 CLI 가 띄운 서버도 첫 야간에 판정되게).
   남아 있는 `.revive` 도 같이.
2. 사용자 `rocky.json` 에 `supervise: true` 와 `nightly` 를 넣고 데몬을 재시작한다.
3. hail-mary 가 옛 주기 · 야간 잡을 끄고 `install.sh` · 결정 기록을 바꾼다(그쪽 승인 · 실행). 순서는 그쪽과 맞춘다.
4. 며칠 `rc/events.jsonl` 로 동작을 본다(이관 조건 ④). 그 뒤 옛 CLI 은퇴(5조각 — 확인 관문).
