# PR 구독 — 감시는 구독한 PR 만, 알림은 구독한 세션에만

2026-10-01 오너 결정. `2026-09-28-pr-watch-design.md` 의 "보드에 레포를 붙이면 그 레포의 PR 을 전부 본다" 를 바꾼다.

## 왜

- **알림이 엉뚱한 세션에 쏟아졌다.** 데몬은 PR 마다 받을 세션을 고르지 않고, 그 레포를 둔 보드에서 가장 최근
  세션 하나에 모든 PR 의 전이를 보냈다 — mdwire 세션이 다른 세션이 만든 #72·#74 의 머지 후보·CI 실패·머지됨을 받았다.
- **비용의 대부분이 안 보는 PR 이었다.** 레포 목록 조회가 레포당 1포인트 × 11 레포 × 3분 = 시간당 약 220포인트
  (2026-10-01 실측). 구독한 PR 의 상세 조회만 남기면 PR 하나에 2포인트 안팎이다.

## 결정

1. **구독 = (레포, PR 번호) → 맡은 세션.** 한 PR 에 하나. 세션 없이 구독할 수도 있다(웹에서 "지켜보기" — 알림 탭에는
   뜨고 세션은 깨우지 않는다). 다른 세션이 다시 구독하면 넘어간다.
2. **누가 구독하나.** `/rocky:review-request` 가 PR 을 만들자마자, `/rocky:review-fix` 를 부른 세션이 그 PR 을
   (`rocky pr subscribe N` — 세션은 `CLAUDE_CODE_SESSION_ID`). 웹 GitHub 탭의 "구독" 버튼(세션 없이).
3. **감시는 구독한 PR 만.** 레포 목록 조회를 하지 않는다 — 구독한 번호만 상세 쿼리로 묻는다(머지·닫힘도 상세가 알려 준다).
   머지·닫힘 전이를 낸 뒤 구독을 걷는다. 구독하지 않은 PR 의 스냅숏은 남기지 않는다.
4. **알림은 맡은 세션에만.** 그 세션의 살아 있는 받은편지함 등록으로 보낸다. 세션이 끝났거나 "보내지 않기" 면 보내지
   않고 전달 기록(`GET /api/deliveries`)에 남긴다. 보드의 다른 세션으로 넘기지 않는다. 배너·브릿지·보드 히스토리는
   그대로(구독한 PR 의 전이만 생기므로 자연히 좁아진다).
5. **구독하지 않은 PR 은 rocky 어디에도 상시로 보이지 않는다**(오너가 받아들임). 대신 GitHub 탭에서 레포를 펼칠 때만
   그 레포의 열린 PR 목록을 한 번 가져와(짧게 캐시) 보여 주고 "구독" 버튼을 단다 — 주기 조회가 아니라 볼 때만 비용.
6. **보드의 `repo`** 는 감시 대상을 정하지 않는다 — 전이 히스토리를 남길 보드를 고르고, `rocky issue` 의 기본 레포다.

## 조각

| 층 | 내용 |
| --- | --- |
| 1 데몬·CLI | `pr_subscriptions` 테이블(마이그레이션 14), REST `GET/POST/DELETE /api/prs/subscriptions`(쓰기는 로컬 전용), tick 이 구독한 PR 만, 라우팅을 구독 세션으로, `rocky pr subscribe|unsubscribe N` |
| 2 플러그인 | review-request·review-fix 가 구독 |
| 3 웹 | GitHub 탭을 레포별로, 펼칠 때 열린 PR 목록(필요할 때 조회) + 구독 버튼 |
| 4 웹 | 알림 탭 — 오너가 손댈 것(머지 후보·결정 필요·막힌 PR·버려진 작업·수집함 새 항목) |

## 나중

- 보드 `prAuthors`(PR 작성자 필터)는 구독이 그 역할을 대신한다 — 걷을지는 따로.
- 세션이 "정하실 것" 을 올리는 `rocky ask` → 알림 탭.
