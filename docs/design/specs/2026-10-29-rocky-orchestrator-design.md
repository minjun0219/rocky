# 로키 오케스트레이터 설계

- 날짜: 2026-10-29
- 상태: 방향 결정(오너, 2026-10-29 "D 안으로 하자"). 구현 전이다. 아래 "열린 질문"이 풀리는 대로 조각별 설계와 PR로 나눈다
- 논의 기록: 프로젝트 스레드 "로키 정체성 다시 정하기"와 그 비교 문서(방향안 A, B, C, D)

## 한 줄

**rocky는 자기 세션을 하나 가진 오케스트레이터 에이전트가 된다.** 오너와 같이 생각하고, 여러 Claude Code 세션을 맡기고
지켜보고 받아 오며, 레포 맥락(worklog)과 오너의 개인 맥락 저장소(캐비닛)를 도구로 찾는다. 데몬(Rust)은 상태와 도구를,
로키 에이전트는 판단과 조율을, 맥 앱(Swift)은 얼굴을 맡는다.

## 왜

- **todo 댓글이 에이전트의 기억으로 동작하지 않는다.** 코드로 확인한 흐름은 이렇다.
  - 사람이 쓴 댓글은 UserPromptSubmit 훅이 다음 프롬프트를 보내는 세션에 한 줄로 넣는다. 본문은 200자로 잘리고
    (`crates/rocky-core/src/notify.rs` `COMMENT_MAX_CHARS`), 보드로 거르지 않아(`crates/rocky-cli/src/hooks.rs`
    `notify_todo_context`) 관계없는 레포의 세션에도 들어간다.
  - 에이전트가 쓴 댓글은 어느 세션에도 다시 들어가지 않는다(`filter_human_changes`). 읽는 길은 `todo_list { id }` 하나다.
  - SessionStart 요약(`rocky_core::summary`)에는 할 일 제목 최대 4개와 수집함 3개만 실린다. 댓글도 worklog도 없다.
  - 같은 진행 내용이 todo 댓글, worklog 턴 기록(`todo:<ref>` 태그), Claude Code 자체 메모리 세 군데로 갈라진다.
- **무게는 이미 세션 관리로 옮겨 갔다.** 에이전트 탭, rc 서버, 세션 띄우기, PR 감시, 기본 브랜치 검증과 자동 배포, 맥 아바타
  (`/api/sessions`를 본다)가 최근 작업의 대부분이다. 이름은 todo 도구로 시작했지만 하는 일은 관제탑에 가깝다.
- **조율은 지금 오너가 손으로 한다.** 어느 세션에 맡길지, 누구를 깨울지, PR을 언제 볼지를 오너가 정한다. 이 판단을 같이 할
  에이전트가 있으면 오너는 결정만 하면 된다.

## 층

| 층 | 언어 | 맡는 것 |
| --- | --- | --- |
| 데몬 `rockyd` | Rust(유지) | 상태와 도구: 세션 목록·띄우기·메시지·깨우기, PR 감시, 검증, 노트, 보안 경계, 설정 REST |
| 로키 에이전트 | 캐비닛 쪽(cabinetd가 돌림, D-112 개정) | 판단과 조율: 캐비닛 `rocky/`에서 뜨는 상주 세션 하나가 rocky 데몬 MCP를 도구로 쓴다 |
| 맥 앱 | Swift(유지) | 얼굴: 아바타, 설정 창, 로키에게 말 거는 입력 칸과 말풍선 |
| 웹 UI | TS(유지) | 폰·원격에서 로키와 대화, 노트, 에이전트 탭 |

Claude Agent SDK는 TypeScript와 Python 판만 있고 Rust 판은 없다. 처음에는 로키 에이전트를 rocky 가장자리의 Bun + TS 프로세스로 제안했지만, 캐비닛 D-112 개정(2026-10-29)으로 로키는 캐비닛에서 cabinetd가 돌리게 됐다. rocky는 로키가 쓰는 데몬과 도구(MCP, REST)를 맡고, 캐비닛 연동 코드를 공개 레포에 넣지 않는다.

## 인증

- **보관**: 둘 다 macOS Keychain. 클라우드 중계소 서비스 토큰처럼 `secretEnv`(환경 변수)가 있으면 그것이 이긴다.
  `rocky.json`과 사용 로그에는 값을 싣지 않는다.
- **보내는 모양**: API 키는 `x-api-key`, OAuth 토큰은 `Authorization: Bearer`와 `anthropic-beta: oauth-2025-04-20`.
  둘을 같이 보내지 않는다.
- **다음 자격 증명으로 넘어가는 때**: 앞 순서의 자격 증명이 없거나, 401·403이거나, 크레딧·한도 소진일 때만. 5xx와
  네트워크 오류는 같은 자격 증명으로 재시도한다. 429를 넘길지는 설정이다.
- **되돌아오기**: 폴백 중에도 일정 간격으로 앞 순서를 다시 시도한다. OAuth 토큰이 만료되면 갱신하고, 모두 안 되면 로키는
  멈추고 맥 아바타·웹으로 알린다.
- **보이기**: 지금 어느 자격 증명으로 도는지를 설정 창과 텔레메트리(자격 증명별 토큰·비용, 폴백 횟수와 이유)에 남긴다.

## 맥 아바타의 지금(main 기준, 2026-10-29)

#511-#523으로 아바타가 새로 만들어졌다. 결정 6과 구현 순서 7은 이것을 바탕으로 한다. 규칙의 정본은 `docs/features/mac.md`.

- **그림**: 오너가 고른 시안의 네 자세(서기, 두 손 흔들며 점프, 머리 긁기, 엎드려 자기)를 윤곽대로 잘라 낸 조각 PNG 20개를 짜 맞춘다. 손으로나 이미지 모델로 다시 그리지 않는다.
- **움직임**: 일하는 세션이 있으면 창 윗면을 걷고, 쪼그렸다 뛰어오르고, 헤일메리 터널 같은 튜브로 다른 창이나 먼 바닥으로 건너간다. 몸짓은 바탕 루프 위에 작은 동작을 가중 랜덤으로 얹어 같은 동작만 되풀이하지 않는다.
- **알리는 것**: 지금은 세션 상태 중 가장 급한 하나(`/api/sessions`를 15초마다). 두 번 누르거나 오른쪽 클릭 메뉴로 웹 에이전트 탭을 연다. 한 번 누르기는 끌기와 헷갈려 아무것도 하지 않는다.
- **로키가 되면 바뀌는 것**: 세션 상태 대신(또는 함께) 로키 자신의 상태(깨어 있음, 생각 중, 묻는 중, 멈춤)를 자세로, 로키의 말을 말풍선으로 보인다. 말 걸기 입구(결정 8)는 한 번 누르기를 다시 쓰지 않고 오른쪽 클릭 메뉴와 단축키로 연다.

## 연동

- **Ollama(선택)**: 자주 돌고, 틀려도 사고가 아니고, 밖으로 나가지 않는 일만 맡긴다. 로키를 깨울지 고르는 이벤트 분류, 턴
  기록 요약과 recall 다이제스트 초안, 맥락 검색용 임베딩, 아바타 말풍선 한 줄. 없거나 꺼져 있으면 지금 규칙으로 돌아간다
  (fail-open). 코드 수정, 세션에 맡길 일의 판단, 머지·배포·외부로 나가는 문장은 Claude 몫이다.
- **cmux**: 오너가 에이전트를 돌리는 터미널(manaflow-ai/cmux)이다. 세션을 cmux workspace·pane으로 띄우기, 사이드바에 세션
  상태 적기를 검토한다. cmux 소켓은 기본적으로 cmux 안에서 뜬 프로세스만 받으므로(`web/DESIGN.md`) 데몬이 직접 부르기보다
  cmux 안의 훅·CLI가 부르는 길이 현실적이다. 알림은 이미 cmux 몫이라 반복하지 않는다.
- **캐비닛**: 맥에서만 닿는다. 그래서 로키 에이전트와 데몬은 맥에서 돈다. 로키 세션은 캐비닛의 `rocky/` 영역을 cwd로 떠서(결정 7) 자기 정체성과 기억을 파일로 읽고, 다른 영역은 캐비닛의 MCP 창구로 묻는다. 클라우드 세션과 폰은 캐비닛을 직접 보지 않고 맥의
  로키에게 묻는다.

## 데몬을 어디에

**Rust 데몬을 그대로 두고 맥 앱 번들 안에 helper로 넣는 쪽을 제안한다.** 앱 안에 두는 장점(한 번에 설치·서명, 앱이 띄우고
내림)은 얻고, 다시 짜는 비용(데몬 + 코어 약 31,000줄)과 GUI 없는 환경(SSH, CLI만)을 잃지 않는다. 훅은 Claude Code가
부르는 명령이라 CLI는 어느 안에서나 남는다.

| 기준 | Swift 앱 안 데몬(재작성) | 별도 Rust 데몬(지금) | Bun + TS 데몬(재작성) | Rust 데몬을 앱에 번들(제안) |
| --- | --- | --- | --- | --- |
| 다시 짤 양 | 약 31,000줄 | 없음 | 약 31,000줄 | 없음 |
| GUI 없는 환경 | 안 됨 | 됨 | 됨(bun 필요) | 됨 |
| 로키 에이전트와 | 멀다 | 프로세스를 나눔 | 같은 언어 | 프로세스를 나눔 |
| AGENTS.md 언어 경계 | 바꿔야 함 | 그대로 | 바꿔야 함 | 그대로 |

## 환경설정

`rocky.json`을 정본으로 두고 데몬이 읽기·쓰기 REST를 낸다. 쓰기는 지금 보안 경계대로 로컬 요청 전용이다. 맥 앱 설정 창이 그
REST를 읽고 쓰고, 데몬 주소·actor처럼 앱 자신의 값만 `defaults`에 남긴다. 좁은 웹 패널에는 두지 않는다(`web/DESIGN.md`).
담을 항목은 로키 에이전트(켜기, 실행 방식, 작업 위치(cwd, 기본은 개인 맥락 저장소), 모델, 하루 예산, 스스로 해도 되는 일, 인증 순서), Ollama, cmux, 캐비닛, 보드·레포
경로, 원격 접속이다. 예산과 자율 범위는 로키가 스스로 넓히지 못하고 사람만 바꾼다.

- 로키가 머지·배포·외부 전송을 스스로 하는 것. 기본은 물어본다.
- 데몬을 다른 언어로 옮기는 것. 위 "데몬을 어디에"의 제안이 받아들여지지 않으면 다시 논의한다.

## 열린 질문

- 구독 계정의 OAuth 토큰을 이런 자체 에이전트에 써도 약관상 괜찮은지, Claude Agent SDK가 OAuth 토큰을 어떻게 받는지.
  구현 전에 공식 문서로 확인한다.
- 캐비닛이 어떤 길(MCP, API, 파일)로 열려 있는지.
- cmux가 workspace 만들기·사이드바 쓰기를 어떤 명령이나 API로 여는지.
- cabinetd가 로키를 Agent SDK로 돌릴지, 상주 Claude Code 세션으로 돌릴지(캐비닛 쪽 결정). rocky는 어느 쪽이든 같은 MCP를 낸다.
- 로키가 스스로 해도 되는 일의 선(예: 세션 띄우기·메시지는 스스로, 머지·배포·외부 전송은 물어보기).
- todo 댓글을 없앨지, 읽기 전용으로 남길지.
- 데몬 배치(앱 번들 제안)를 받아들일지.
- 로키에게 말 거는 입구(결정 8) 중 무엇을 먼저 만들지: 맥 아바타, 웹 로키 탭, CLI. 로키 에이전트 시험(구현 순서 6)과 같이 가야 답할 상대가 있다.

## 구현 순서

1. `rocky usage --since 90d`로 댓글·노트·보드·에이전트 탭 사용 횟수를 본다.
2. AGENTS.md·README의 정체성 문장을 고친다(#516, 끝남).
3. SessionStart에 이 작업 경로(워크트리 루트)에서 남긴 decision·blocker와 recall 다이제스트를 몇 줄 싣는다. 기억이 실제로 읽히는 첫 연결이다. 레포 전체가 아니라 작업 경로가 범위다(오너 2026-10-29, `rocky_core::memory_brief`, 끝남).
4. 내보내기 명령을 만들고 기존 댓글을 캐비닛으로 옮긴 뒤 todo 댓글을 뺀다.
5. 캐비닛 연결 설계.
6. 로키 에이전트 시험: 캐비닛 `rocky/`에서 뜬 상주 세션 하나에 데몬 MCP만 도구로 주고, 이벤트(PR 머지 후보, 기다리는 세션)와 오너가 말을 걸 때(결정 8)만 깨운다. 첫 입구는 하나만 붙인다.
7. 지금 아바타 위에 로키 자신의 상태와 말풍선, 말 걸기 입력 칸을 얹는다. 설정 창을 더한다.
