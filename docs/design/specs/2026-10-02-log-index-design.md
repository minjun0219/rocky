# 로그 색인 — 작업로그·사용 로그를 보드에서 읽고 분석한다

2026-10-02. 오너 요청: 작업로그를 보드에 통합(별도 탭 + 할 일 상세), 로그를 회고와 rocky 개선 둘 다에 쓴다.

## 목적

- **회고** — 무엇에 시간을 썼나, 어디서 막혔나(레포·할 일·기간별).
- **rocky 개선** — 느린 표면, 실패하는 표면, 안 쓰는 표면.
- 할 일 댓글은 사람에게 1~3줄로 두고, 작업 흐름은 작업로그에서 본다(세션이 댓글에 인수인계를 길게 쓰지 않게).

## 제약

- 데스크톱 중심 기기(회사)에서 주로 쓴다 — 작업로그는 업무 맥락이라 **기기 밖으로 보내지 않는다**(외부 분석 서비스 없음).
  기기 간 동기화도 없다.
- 디스크 작업로그(JSONL 모양·키 순서·프로젝트 키)는 호환 계약이다 — 바꾸지 않는다.
- 데몬이 꺼져 있어도 기록은 남아야 한다(Stop 훅은 fail-open, 데몬 교체가 잦다).
- 보드(`todo.db`, 연결 하나 + `Mutex`)를 느리게 하지 않는다.

## 구조

```
쓰기(그대로)                         색인(새로)                      읽기
Stop 훅 / worklog_append ─▶ worklog/<key>/worklog.jsonl ─┐
REST·CLI·훅·웹 사용 로그 ──▶ usage/YYYY-MM.jsonl ─────────┼─▶ 색인 스레드 ─▶ logs.db ─▶ GET /api/logs/* ─▶ 웹(작업로그 탭·할 일 상세·통계)
                                                         │   (1분마다, 증분)              ▲
                                                         └──────────────────────────────── /rocky:recall 도 기간·레포로 걸러 읽는다
```

- **JSONL 이 진실, DB 는 파생 색인.** `logs.db` 는 지워도 데몬이 다시 만든다.
- **별도 파일** `~/.config/rocky/todo/logs.db` — `todo.db` 와 장애·잠금을 나눈다.
- **전용 OS 스레드 하나**(`std::thread`)가 자기 연결로 색인한다 — `todo.db` 잠금도 tokio 워커도 쓰지 않는다.
  조회는 `spawn_blocking` + 읽기 전용 연결(WAL 이라 색인 중에도 읽힌다).
- 증분: 파일마다 읽은 바이트 위치(`log_files(path, offset, size, mtime)`). 파일이 줄었으면 처음부터. 마지막 줄이
  `\n` 없이 끝나면(쓰는 중) 그 줄은 다음 바퀴로 미룬다. 기동 때 한 번, 그 뒤 1분마다.
- 중복: 작업로그는 `id` 가 기본키(`INSERT OR IGNORE`). 사용 로그는 id 가 없어 `(file, offset)` 을 키로.

## 표

- `worklog_entries(id PK, project_key, timestamp, kind, content, tags JSON, todo_ref NULL)` — `todo_ref` 는 태그
  `todo:<ref>` 에서 뽑는다.
- `usage_events(file, offset, ts, source, name, actor, client, ok, ms, PK(file, offset))`.
- 보드 ↔ 프로젝트 키: 데몬이 보드 `path` 로 `default_project_key` 를 계산한다(같은 함수 — 골든 테스트가 고정).

## 할 일과 연결

Stop 훅(`log-turn`)이 턴을 쓸 때 그 세션이 든 진행 중 할 일(`held_by_session`)이 있으면 태그에 `todo:<ref>` 를
더한다. 이 기능 이전의 턴은 태그가 없어 할 일 상세에 나오지 않는다(보드 탭에는 나온다).

## 화면

- **작업로그 탭** — 고른 보드(레포)의 기록을 시간순으로, "전체" 면 전 보드. 종류 필터·검색(`LIKE`, 느리면 FTS5).
- **할 일 상세** — 타임라인에 "작업" 줄(접힌 한 줄, 펼치면 본문)로 댓글·히스토리 사이에 끼운다.
- **통계**(작업로그 탭 안의 한 칸, 처음엔 작게)
  - 회고: 레포·요일별 턴 수, 할 일별 `start`→`done` 시간과 붙은 턴 수.
  - 개선: 느린 표면 상위(중앙값·p95 `ms`), 실패율 높은 표면(`ok:false`), 90일 안 쓴 표면(기존 `rocky usage`).
  반복해서 보는 질문만 둔다 — 처음엔 위 다섯 개, 더하는 건 쓰면서.

## 나누기 (PR 스택)

1. 데몬: `logs.db` 색인 스레드(작업로그 + 사용 로그) + `GET /api/logs/worklog`(board·todo·kind·q·limit).
2. Stop 훅: `todo:<ref>` 태그.
3. 웹: 작업로그 탭 + 할 일 상세 "작업" 줄.
4. 통계: `GET /api/logs/stats` + 탭 안의 통계 칸.

## 하지 않는 것

- 저장소를 데몬으로 옮기기(쓰기 경로 변경) — 데몬이 꺼진 동안의 기록을 잃는다.
- 외부 분석 서비스로 보내기, 기기 간 합치기.
- 별도 프로세스(색인 데몬) — 스레드로 충분하고, 프로세스가 늘면 기동·교체·버전 맞추기가 두 벌이 된다.
- HTTP 핸들러의 동기 SQLite 호출 정리 — 지금 규모에선 문제가 아니다. 보드가 느려지는 게 보이면 그때.
